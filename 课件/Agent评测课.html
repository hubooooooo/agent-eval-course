评测是什么
Definition · 定义
评测（Evaluation，简称 Eval）：对 Agent 的效果做系统性度量的一套方法
它回答的问题一
好不好
给判断

What · 量具
评测是一套“精密量具”
要求一
要准
  • 人人一致：不同的人打分一致
  • 人机一致：人和机器打分一致
类比同一条视频，两个审核员，一个过、一个不过
要求二 · 最容易被忽略
要定期校准
  • 用户变了
  • 功能变了
  • 业务目标变了
→ 原有的题目和标准逐渐失去代表性

Why · 三种结局
没有评测的三种结局
01
停在演示
演示很好，一接真实流量就覆盖不住
02
卡在放量
小范围还行，一放量问题集中暴露，说不清错在哪一层
03
说不清业务价值
迭代了几十版，拿不出变好的证据
共同原因：缺少可靠的判断机制，决策靠感觉和个别案例
Why · 两个原因
Agent 比传统软件更需要评测
Before
传统软件
输出
相同输入 → 相同输出
出错时
崩溃、弹出提示
Now
Agent
输出
有随机性：同一任务执行多次，结果可能不同
出错时
不会报错：照样交出看起来完整可信的结果
Term · 术语
幻觉（Hallucination）：模型自信地给出错误内容

How · Step 2
第二步 · 定义评分标准
Definition · 定义
Rubric（评分细则）：最小粒度的评价标准，每一条只能回答是或否
无法打分
“这份 PPT 做得好不好？”
→
二元化 · 拆成是或否
是否产出了文件是 / 否
投放金额是否与源数据一致是 / 否
是否包含同比或环比分析是 / 否
目的：消除分歧，提高人人一致率和人机一致率
How · Step 2
评分标准要分层
第一层 · 决定任务是否成功
成功必需项
  • 全部通过，任务才算成功
  • 一票否决：安全类、数据准确性类
  • 例：未经确认的写操作、数据外发
第二层 · 不影响任务是否成功
质量诊断项
  • 用于发现优化空间

How · Step 3
第三步 · 判定：谁来判
Grader：执行判定的程序，分两种
用规则和代码判定
确定性 Grader
适合：能从执行记录里精确取证的检查项
类比数据面板：击杀、补刀、伤害自动统计
用大模型判定 · 也叫 LLM Judge
LLM Grader
适合：需要理解语义的检查项
类比教练看录像点评：这波团该不该开
设计细节：证据不足的高风险问题，允许 LLM Grader 返回“无法判断”

How · Step 5
第五步 · 观测：Trace
Definition · 定义
Trace
Agent 一次执行的全链路记录
  • 每一次模型调用的输入输出
  • 每一次工具调用的输入输出
类比对局回放
最小可归因：凭 Trace 能复现错误是怎么发生的
TRACE · 示意
01用户输入检查昨天的广告投放
02模型调用规划：先查数据，再出报告
03工具调用查询投放数据 · 日期 = 今天← 错在这一步
04模型调用生成巡检报告
05最终输出一份结构完整的报告
